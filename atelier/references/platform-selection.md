# Platform & stack selection — pick the best fit for THIS project, any provider, free-first

Standing requirement: the factory is **not locked to Azure**. For each project it evaluates what the project actually needs and recommends the best-fit platform and stack — which may be Azure, AWS, GCP, Oracle, Vercel, Cloudflare, Netlify, Render, Fly.io, a self-hosted/open-source setup, or nothing more than a free static host — chosen by **project fit under the cost posture**, not by loyalty to one cloud. Azure stays a default **only where it is the best free fit and you hold credits**; otherwise the factory recommends what genuinely fits. This supersedes the earlier "host on Azure" default: Azure is now one strong option among several, not the automatic choice.

## How it chooses (evaluate the project, then match the cheapest option that clears the bar)
1. **Classify the real needs** (from the plan/SPEC): static vs server-rendered vs long-running server; database (and type); background work (cron, queue, worker, websockets); edge/low-latency; special runtime (Python/Go/Rust, containers, GPU); data residency/compliance; expected scale.
2. **Match to the cheapest option that meets the bar**, provider-agnostic, free-first (`cost-posture.md`):
   - **Static site / SPA / Next static export** → a free static host: **GitHub Pages, Cloudflare Pages, Netlify, Azure SWA Free, Firebase Hosting, S3+CloudFront free tier**. Pick by the user's existing accounts + simplicity. $0.
   - **Next.js / full-stack with a managed DB** → **Azure SWA Free + Supabase** (default when you hold Azure credits), or **Vercel Hobby** (non-commercial) / **Netlify** / **Cloudflare** + Supabase, or **Render**/**Railway** free for a single service. $0 at small scale.
   - **A real server / container / background work** → a scale-to-zero container host: **Azure Container Apps** (consumption, min-replicas 0), **GCP Cloud Run** (generous free tier), **Fly.io** (free allowance), **Render** (free web service), **AWS App Runner / Amplify**. Pick the best free fit for the runtime.
   - **Always-on box / open-source self-host** → **Oracle Cloud Always Free** ARM VM (up to ~24GB — verify current terms; ARM capacity scarce) running open-source (Docker Compose, Coolify, Dokku, Caddy) — when the project wants to own the stack, avoid per-service limits, or needs a persistent server at $0.
   - **Database** → **Supabase free** (Postgres+auth+storage) by default; alternatives: **Neon, PlanetScale, Turso, Cloudflare D1**, or a self-hosted Postgres on the Oracle box — free tiers first.
3. **Weigh what you already have.** If you hold cloud startup or trial credits (an Azure startup grant, Oracle's ~$300 trial, and the like), use them for the *overflow* a free tier can't cover, so credits — not cash — absorb it. Don't stitch five providers together to save a dollar; keep it minimal (one host + one DB) unless the project needs more.
4. **Always consider the open-source / free-tool option.** When a self-hosted or open-source setup genuinely fits and stays free (and the user can run it), offer it alongside the managed option, with the honest trade-off (you own the upkeep).

## Present it (one plain recommendation, the user picks)
State the recommended stack + platform in **one plain line** with the reason and the cost — e.g. "Recommended: **Cloudflare Pages + Supabase — $0/month**, a static site wants the fastest free global edge" or "Recommended: **GCP Cloud Run + Supabase — $0 at this scale**, you need a Python server that scales to zero." Then, with AskUserQuestion, offer 2–3 real alternatives (including Azure, and an open-source/self-host option when it fits), each one line with its **pros, cons and cost** (per `recommendations.md` — never the upside alone; name the real downside: a free tier that sleeps, upkeep you own, lock-in). **The user chooses.** Record the choice as `brief.stack` + `brief.deploy_hint` (a target name) in `factory.json`.

## Cost posture holds across every provider
Free-first is **provider-agnostic**: the cheapest option that clears the bar wins — free before our credits before paid — and a stated budget never unlocks a paid tier the project doesn't need (`cost-posture.md`). The contracts (performance, security, SEO, compliance, design) are met the same on whatever platform is chosen. A paid tier on any provider is proposed only when a real requirement forces it, with the monthly price, on an explicit yes.

## Deploying to the chosen platform
If the chosen platform has a file in `references/targets/`, `/pf-deploy` follows it. If it is a provider not yet in the registry, **add a target file** for it (Fits, Env vars, Deploy steps — build locally and upload, never a remote/paid build; Health check; Custom domain) — the registry is extensible by design. Self-hosted/open-source targets deploy by the documented steps for that stack (e.g. `docker compose up -d` behind Caddy on the Oracle box) and still build locally. The one-time account/CLI/credential setup for the chosen platform is run by `/pf-setup project <slug>`.
