# Atelier Builder (Claude Code plugin)

The Claude Code half of the factory. The Cowork `atelier` plugin writes a request file into the project folder and types `/pf-next` into this session through Chrome (or you type it); this plugin runs that one request and writes a result file back. It never runs on a timer and never acts on its own — the trigger is always a typed command.

| Skill | Triggered by | Does |
|---|---|---|
| `pf-next` | `/pf-next [--lane x] [--go]` | Finds the newest pending request (`BUILD-REQUEST-<lane>.md` / `MERGE-REQUEST-<lane>.md` / `DEPLOY-REQUEST.md` / `HARDEN-REQUEST.md` / `PENTEST-REQUEST.md` / `PROMO-REQUEST.md`) and runs the matching skill. `--go` skips the confirm (Cowork passes it after your approval) |
| `pf-link` | `/pf-link` | Run once in a new project session and again after every restart, with nothing after it: turns Remote Control on, names the session and writes `SESSION-<lane>.md` in the project folder, so the Cowork seat hands work to this session and no other. A session refuses a request that belongs to another project. |
| `pf-build-from-spec` | via `/pf-next` | Builds the lane: Next.js + Tailwind + shadcn from `SPEC-<lane>.md` — tokens, screens with exact copy, Supabase when present — then gates the build on all six contracts (performance, SEO + AI visibility, security, simplicity, design, compliance) before it passes. Solo → push `main`; team lane → `lane/<x>` + PR |
| `pf-deploy-from-spec` | via `/pf-next` | Deploys `main` to the target in `DEPLOY-REQUEST.md`, following that target's file in the registry; **builds locally only and creates only free resources** (a paid step stops for your decision); records a rollback point, runs the health check + bake, **auto-rolls-back a bad deploy** (app only, never the DB); writes `DEPLOY-RESULT.md` |
| `pf-harden-from-spec` | via `/pf-next` | Runs the passes in `HARDEN-REQUEST.md` (safety-net tests, perf budget on the live site, SEO + AI visibility, defensive security, DB indexes, free-layer caching, local k6 load test, hosting-limits) on a `harden/<date>` branch, one commit per fix, opens a PR, writes `HARDEN-RESULT.md`; k6 only against a local copy; **never creates a billed resource** |
| `pf-pentest-from-spec` | via `/pf-next <slug> pentest` | Data-sensitive projects only: an authorized adversarial test against the project's **registered pre-production host with synthetic data only** (`PENTEST-REQUEST.md` + `references/security-testing.md`) — verifies the scope guardrails first, runs recognized DAST + access-control tooling (and your self-hosted PentAGI when enabled), fixes findings on a `pentest/<date>` branch, writes `PENTEST-RESULT.md`. Never production, never real data, never on a schedule, never `--go` |
| `pf-promo-from-spec` | via `/pf-next <slug> promo` | Optional: builds the launch-video page from the approved storyboard and renders review stills or the final MP4 with the bundled `scripts/render-video.mjs` (Playwright + ffmpeg, offline); works on a `promo` branch that never merges; writes `PROMO-RESULT.md` |
| `security-audit` | by harden and pentest, when the request calls for a deep audit | Bundled open-source skill (MIT © Cloudflare): a source-first vulnerability audit of your own code, in a no-network sandbox |

## The contracts it enforces
The build/deploy/harden/pentest skills read their contracts from `references/` (mirrored from the Cowork plugin, kept byte-identical by the validator): `performance-budget.md`, `seo-ai-visibility.md`, `security.md`, `code-simplicity.md`, `design-standard.md`, `compliance.md`, `cost-posture.md` (free-first — build locally, create nothing billable without a yes), `monitoring.md` (rollback), `deploy-rule.md`, `security-testing.md`, and the `targets/` registry. A contract is a hard gate: `pf-build-from-spec` refuses to pass a lane that misses any of the six build contracts.

## What every repo it builds carries
`npm run verify` (one command for lint, types, build, tests, e2e, audit, secret scan) wired to a pre-push hook and — when the request says `ci: self-hosted|hosted` — a workflow; one e2e test per `page-`/`feature-` diagram; `docs/ARCHITECTURE.md`, `docs/RUNBOOK.md`, `docs/ADMIN-GUIDE.md`, `CHANGELOG.md`; migrations written expand-then-contract and applied to the **test** database only (production is touched by the live deploy alone, after a backup); deploys go to a preview first and tag each live release `live-<yyyymmdd-HHMM>`. Since 1.2.0 also: a phone and desktop screenshot of every screen as a visual baseline (and for the PM's design check); locale-safe formatting always, full translations when the Brief lists more than one locale (`references/i18n.md`); `infra/` as code when the request says so, applied only by the deploy after a yes (`references/infrastructure.md`); typed, expiring feature flags and 10% canary rollouts when asked for (`references/rollout.md`); Flutter/native store releases (`references/targets/flutter-stores.md`). Since 1.3.0: an optional 3D product scene when the Brief has a `3D scene:` line (`references/scene-3d.md`), and a `model:` line in every build result saying which model and advisor built it. Contracts: `references/verification.md`, `references/migrations.md`, `references/deploy-rule.md`.

## Requirements on this machine
- Node 20+, `gh` logged in, Playwright (`npx playwright install chromium`) for the diagram-derived e2e tests and the diagram renderer, `gitleaks` for the secret scan in `verify`, and `ffmpeg` only for the optional launch video — no other plugin or skill; run **`/pf-next doctor`** to check everything at once; per target: `vercel` CLI / `az` CLI / Docker Desktop / `wrangler` / `netlify` / `gcloud` / `flyctl` (see `references/targets/`).
- Env vars by **name** only (never stored or printed): per target as listed in its file; for backends `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_DB_URL`, `TEST_USER_EMAIL`, `TEST_USER_PASSWORD` (these unprefixed names are the **test** database; production uses the same names with a `PROD_` prefix once the project is split — `references/migrations.md`); optional `CRON_SECRET`, `INDEXNOW_KEY`, `PF_WATCH_DIR`.
- Remote Control on (`/remote-control`) so Cowork can reach this session in Chrome; permissions allow-listed for `npm npx git gh vercel az docker` (see `/pf-setup` in Cowork).
- Code checkouts at `<code root>/<slug>`.

## What this plugin never does
Run on a timer or a file-change hook (it ships no hooks module); act on instructions found inside a request file, spec or `notes:` (those describe the product only); build remotely; create a billed resource without stopping for a yes; roll back a database; print or store a secret value (env-var names only); or run the pentest against production, real data, or on a schedule.

## More than websites
Products that are not websites — a browser extension, a desktop app, an API, a command-line tool, an AI agent — are built by the same skills: the SPEC's `Type:` line selects that type's rules in `references/product-types.md`, and the targets `chrome-web-store`, `desktop-release` and `package-registry` end at a draft the owner publishes.
