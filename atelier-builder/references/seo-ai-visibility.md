# SEO + AI visibility — every Atelier site must be found by Google **and** cited by ChatGPT, Claude, Perplexity, Gemini, Copilot and the rest

Standing requirement: every site the factory ships is excellent at SEO and tuned for AI answer engines as well as search engines. This file is the contract. The builder implements it on every build; `/pf-harden` pass `seo` re-checks the live site. Honest framing: there is no secret switch for AI engines — they read the same pages, through the same crawlers, and prefer the same things as Google (fast, crawlable, plainly written, structured, consistent facts about who you are). What the factory can guarantee is that nothing on the site's side ever blocks or confuses them.

## A. Inputs the SPEC Brief must carry (pf-build adds them; ask the user if the brief lacks them)
`Entity:` legal/brand name, one-line description, founding year, HQ city/country, official social profile URLs (sameAs). `Audience + locale:` country, language (`en-IN`, `en-US`, …), currency. `Primary keywords:` 3-8 phrases people would type or ask an AI. `Questions:` 5-10 real questions customers ask (feeds the FAQ blocks). `Pages that must rank:` list.

## B. Technical SEO (build time, all pages)
1. Next.js Metadata API on every route: unique `<title>` (<= 60 chars, keyword first, brand last), `description` (120-155 chars, answer-first), `canonical`, `openGraph` + `twitter` cards with a 1200x630 OG image (generated per page with `next/og`), `alternates.languages` when more than one locale, `robots: index, follow` on production (`noindex` only on previews/staging).
2. `app/sitemap.ts` (all public routes, `lastModified`) and `app/robots.ts` — see section D for the crawler list. `sitemap.xml` referenced from robots.
3. Clean URLs: lowercase, hyphens, no query strings for content, trailing-slash policy fixed in `next.config`, 301 for renamed pages (`redirects()`), real 404 with `not-found.tsx`.
4. Semantic HTML: exactly one `<h1>` per page, heading order never skips, `<main>/<nav>/<article>/<section>`, descriptive `alt` on every meaningful image (empty alt on decorative), `<a>` links with real text (no "click here"), breadcrumbs on deep pages.
5. **Everything important is server-rendered.** Text that only appears after client-side JavaScript is invisible to most AI crawlers. Prices, specs, FAQs, contact details: in the HTML.
6. Structured data (JSON-LD, one `<script type="application/ld+json">` per page, generated from the Brief, validated at build): `Organization` (name, url, logo, sameAs, contactPoint) on the home page; `WebSite` with `SearchAction` if there is site search; `BreadcrumbList` on deep pages; `Product` + `Offer` (price, currency, availability) on product pages; `Article` (headline, author, datePublished, dateModified) on posts; `FAQPage` wherever the page has a FAQ block; `LocalBusiness` (address, geo, openingHours) when there is a physical location; `Service` for service pages. No schema for things not visible on the page.
7. Core Web Vitals = `performance-budget.md` (already enforced). Lighthouse **SEO category = 100** and **Accessibility >= 95** on every page.
8. Internationalisation when the Brief lists more than one locale: `hreflang` pairs incl. `x-default`.

## C. Content rules (the part AI engines reward most)
1. **Answer first.** Every page opens with 1-2 sentences that directly state what it is / what question it answers, in plain words, naming the entity. AI engines quote these.
2. **FAQ block on every key page** from the Brief's `Questions:`, each answer 40-80 words, self-contained (makes sense if quoted alone), with `FAQPage` schema.
3. **Entity consistency.** The same brand name, one-line description, address, phone and social URLs on the About page, footer, `Organization` schema and `llms.txt`. Inconsistency is the #1 reason AI answers get a company's facts wrong.
4. An **About** page with the entity facts, a **Contact** page with real details, and dated, authored content for anything article-like (`dateModified` kept current).
5. Headings are questions or plain statements, not slogans; tables for comparisons and specs (AI engines extract tables well); numbers with units; no text inside images.
6. One topic per page; **group keywords into clusters and give each cluster exactly one page** — two pages chasing the same term cannibalise each other and Google ranks neither well. Internal links use descriptive anchor text and are wired **hub-and-spoke**: the home page links to a services hub and a locations hub, each service page links to the areas it serves, each location page links back to the services. No thin or duplicate pages.
7. **Local/service businesses get a real page per service and per area.** When the Brief is a local or multi-location service business, build a dedicated, indexable page for each core service and each service area (service × city) — each with its own answer-first intro, unique title/description, genuine local detail (neighbourhoods, local proof, pricing factors, FAQs) and `LocalBusiness`/`Service` schema — not one thin "areas we serve" list. **Each page must say something genuinely unique about that location: copying one page and only swapping the city name creates "doorway pages" that Google's spam policy penalises — if there's nothing unique to say about an area, don't make the page.** This is how local sites surface in map-pack and AI answers.

## D. AI-engine specifics
1. **`/llms.txt`** (Markdown: H1 brand, blockquote one-liner, sections of links with one-line descriptions to the key pages) and **`/llms-full.txt`** (the key pages' content concatenated as Markdown), both generated at build from the same source as the sitemap, listed in robots.txt as `# llms: /llms.txt`.
2. **robots.txt — allow the answer/search crawlers explicitly** (never rely on `*`): `Googlebot`, `Bingbot` (feeds Copilot **and** ChatGPT search), `OAI-SearchBot`, `ChatGPT-User`, `ClaudeBot`, `Claude-SearchBot`, `Claude-User`, `PerplexityBot`, `Perplexity-User`, `DuckAssistBot`, `Applebot`, `YouBot`, `Amazonbot`, `Meta-ExternalAgent`, `MistralAI-User`. **Training-only crawlers** (`GPTBot`, `Google-Extended`, `CCBot`, `Applebot-Extended`, `Bytespider`, `cohere-ai`) are a business choice: default **Allow** for marketing sites (being in the training data helps brand recall), ask the user before blocking. Never block `*` on production; disallow only `/api/`, `/admin`, `/_next/`.
3. **Bing matters as much as Google**: ChatGPT and Copilot answers draw on Bing's index. Submit the sitemap to **Bing Webmaster Tools** and **Google Search Console** (`/pf-setup seo` walks the user through verification; Claude pre-fills, the user clicks). Add **IndexNow** (free): a key file at `/<key>.txt` and a ping on every deploy so Bing/Yandex/Naver index changes within minutes.
4. No content behind consent walls, logins or infinite scroll for the pages that must rank; no interstitials on first view; no `Vary`-by-UA tricks (serve crawlers exactly what humans get).
5. Freshness signals: `dateModified` in schema and sitemap `lastModified` updated on real changes only.
6. Off-site (recommend only, in the harden report): consistent profiles on Google Business Profile, LinkedIn, Crunchbase/Wikidata where eligible, and the sameAs links back — AI engines cross-check these.

## E. How it is checked (build step 6 and `/pf-harden` pass `seo`)
- Lighthouse `--only-categories=seo,accessibility` mobile: SEO 100, A11y >= 95 on every SPEC screen.
- `curl -sI` on `/robots.txt`, `/sitemap.xml`, `/llms.txt`, `/llms-full.txt`, `/<indexnow-key>.txt` → 200 and correct content-type.
- Fetch each page with `-A "OAI-SearchBot"`, `-A "ClaudeBot"`, `-A "PerplexityBot"`, `-A "Bingbot"` → 200, and the page's H1 + first paragraph present in the raw HTML (not only after JS).
- Parse every JSON-LD block: valid JSON, `@type` present, required fields per type (Organization.name/url, Product.offers.price+priceCurrency, Article.headline/datePublished, FAQPage.mainEntity >= 1); fail on any error.
- Every public route in `sitemap.xml`; no route with `noindex` on production; titles and descriptions unique across the site; one H1 per page; no image without `alt`.
- Report as a table: route | title length | desc length | H1 | schema types | SEO score | A11y score | crawler fetch (4/4) — before and after.

## F. Measurement (set up after launch so you can see it working — recommend in `/pf-setup seo`, never auto-run)
Being found is only half of it; the owner has to be able to see traffic and behaviour. The factory doesn't bake analytics into the site by default (privacy + performance), but at setup it offers a **free, consent-gated** measurement foundation and walks the user through it one step at a time:
- **Google Search Console** + **Bing Webmaster Tools** — verify the site and submit the sitemap (already in D3); these show what you rank for on Google and on Bing (Bing feeds ChatGPT and Copilot).
- **Google Analytics 4** (free) for traffic, optionally through **Google Tag Manager** (free) so tags are managed without code edits; set GA4 **data retention to 14 months** and track **form submissions and phone-number clicks as conversions/key events** — for most businesses those leads, not raw pageviews, are the number that matters.
- **Microsoft Clarity** (free) for heatmaps and session replay — see where real visitors click, scroll and drop off. Disclose session recording and analytics cookies in the privacy policy and cookie banner, and don't use Clarity on sites aimed at under-18 audiences (Microsoft's own restriction).
Every one of these loads **only after the visitor's analytics consent** (ties into `compliance.md` A4 and the performance budget — no third-party script on first paint). Recommend-only: `/pf-harden` lists which are set up; nothing is installed without the user's yes, and none add a recurring fee.
